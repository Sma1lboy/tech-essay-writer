# Tutorial Article Template

## Target Audience & Expertise Level
- **Primary**: Developers who know the basics but haven't built this specific thing
- **Expertise**: Beginner-to-intermediate (can read code, knows fundamentals, needs guided path)
- **Prerequisite knowledge**: Comfortable with the language/framework basics; no need for expert-level understanding

## Recommended Word Count: 1500-3000 words

## Structure
1. **Hook** — What you'll build / learn (with screenshot or result preview)
   - *Purpose*: Immediately show the end result to hook the reader's curiosity
   - *Transition*: From "here's what you'll have" to "here's what you need to start"
2. **Prerequisites** — What you need to know / have installed
   - *Purpose*: Set clear expectations so readers don't hit walls mid-tutorial
   - *Transition*: From "what you need" to "let's set it up"
3. **Setup** — Environment, dependencies, starter code
   - *Purpose*: Get every reader to the same starting point, regardless of their machine
   - *Transition*: From "ready to go" to "let's build the first piece"
4. **Step-by-step implementation** — Each step with code + explanation
   - *Purpose*: The core teaching sequence; each step builds on the last
   - *Transition*: Each step ends with a verifiable checkpoint ("you should see X")
5. **Testing / Verification** — How to know it works
   - *Purpose*: Prove the tutorial delivers on its promise
   - *Transition*: From "it works" to "what can go wrong"
6. **Common pitfalls** — Things that go wrong and how to fix them
   - *Purpose*: Address the top 3-5 errors readers will actually hit
   - *Transition*: From troubleshooting to growth
7. **Next steps** — Where to go from here
   - *Purpose*: Give the reader a clear path forward after completing the tutorial

## Example Hooks
- "In the next 20 minutes, you'll build a real-time notification system that handles 10k concurrent users. Here's what it looks like when you're done:"
- "By the end of this tutorial, you'll have a working CLI tool that does X — and you'll understand every line of code."
- "I spent 3 days figuring out how to wire these together. This tutorial gives you the result in 15 minutes."

## Tone
- Direct, practical, "let me show you"
- Second person ("you'll create", "you need to")
- Code-first — show the code, then explain
- Encouraging but not patronizing — assume competence, explain context

## Code Density: High (40-50%)

## Target Length: 1500-3000 words

## Anti-Patterns
- **Wall-of-code**: Dumping 50+ lines without explanation; break into digestible chunks of 5-15 lines
- **Missing verification steps**: Each major step needs a "you should now see X" checkpoint
- **Assumed environment**: Never assume the reader's OS, editor, or shell — be explicit about setup
- **Outdated dependencies**: Pin specific versions and note the date; readers will find this months later
- **Skipping error handling**: Show what happens when things go wrong, not just the happy path
- **"Just do X"**: Every instruction needs a "why" — even if brief

## Reader Promise
"After reading this, you can build X yourself"
